# ۰۵ — پنل مشتری سازمانی: ورود و کارکنان (Back + Front)

**وابستگی:** OW-04.
**خروجی:** پنل سازمان در `jayab.app/org` (E12) با پذیرفتن دعوت و ورود مدیر، چند مدیر، داشبورد، کارکنان (دستی، گروهی و اکسل)، ویرایش شماره با کد تأیید، و فعال و غیرفعال کردن کارمند. شارژ کارکنان در OW-06 است.

**مرجع طراحی:** تصویرهای ۱ و ۲ کارفرما (منو، کارت‌های آمار، جدول کارکنان، modal افزودن و شارژ، modal ویرایش شماره). ظاهر از design system Front است، با سه زبان و دو تم (XC-4).

---

## OW-5.1 — مدل کارمند

```prisma
model OrganizationEmployee {
  id              Int       @id @default(autoincrement())
  organization_id Int
  full_name       String
  mobile          String    @db.VarChar(11)
  department      String?   @db.VarChar(64)
  status          Int       @db.SmallInt          // 10 ACTIVE, 20 INACTIVE
  user_id         Int?                            // linked on the employee's first login (OW-07)
  created_by      Int                             // manager user id
  created_at      DateTime  @default(now())
  updated_at      DateTime  @updatedAt
  @@index([organization_id, status])
  @@index([mobile])
  @@map("organization_employees")
}
```

**یکتایی شماره (تصمیم کارفرما ۵):** هر شماره فقط در یک سازمان می‌تواند **فعال** باشد. Prisma ایندکس یکتای شرطی ندارد، پس در migration با SQL خام:

```sql
CREATE UNIQUE INDEX "organization_employees_active_mobile_key"
  ON "organization_employees" ("mobile") WHERE "status" = 10;
```

- شمارهٔ کارمند غیرفعال آزاد می‌شود. اگر همان شخص بعداً در سازمان دیگری فعال شود، اعتبار باقی‌ماندهٔ قبلی‌اش به ردیف قدیم وصل می‌ماند تا انقضا (E9).
- حساب کیف پول کارمند (`EMPLOYEE_ORG_CREDIT`) با `employee_id` است، نه با شماره. پس تغییر شماره اعتبار را جابه‌جا نمی‌کند (بخش ۱۰ تصویر ۱).

## OW-5.2 — ورود مدیر

- **پذیرفتن دعوت:** `Front/app/(org)/org/invite/[token]/page.tsx`.
  - اگر کاربر وارد نشده، به ورود OTP موجود با `redirect_url` همین صفحه می‌رود.
  - بعد از ورود، `POST /api/v1/org/invites/:token/accept` صدا زده می‌شود.
  - **Back:** token معتبر و منقضی‌نشده باشد و **موبایل کاربر واردشده برابر `mobile` دعوت** باشد، وگرنه 403 با `ORG_INVITE_MOBILE_MISMATCH`. سپس `user_id` و `status = ACTIVE` تنظیم و token پاک می‌شود.
- **گارد:** `OrgManagerGuard` در `Back/src/organization/guards/`. همهٔ APIهای پنل سازمان زیر `org/:orgId/...` هستند و گارد بررسی می‌کند کاربر مدیر `ACTIVE` همین `orgId` باشد و سازمان `ACTIVE` و `ORG_PLAN_ENABLED` روشن باشد. **هیچ داده‌ای بدون این گارد برنمی‌گردد.**
- **چند سازمان:** `GET /api/v1/org/mine` فهرست سازمان‌هایی را که کاربر مدیرشان است برمی‌گرداند. اگر بیش از یکی باشد، Front انتخاب‌گر سازمان نمایش می‌دهد و `orgId` در URL است: `/org/{orgId}/...`.
- **مدیران (E10):**
  - `GET` و `POST /org/:orgId/managers` با حداکثر ۵ مدیر. دعوت با همان پیامک OW-4.2 انجام می‌شود.
  - `DELETE /org/:orgId/managers/:mid`. مدیر نمی‌تواند خودش را وقتی آخرین مدیر است حذف کند.

## OW-5.3 — APIهای کارکنان

| متد | مسیر | کار |
| --- | --- | --- |
| GET | `/org/:orgId/dashboard` | `{ employees: { total, active, with_credit }, credit: { charged, spent, remaining, spent_percent }, org_balance, recent_transactions[], expiring_soon }`. `org_balance` جمع موجودی `AVAILABLE` کارکنان است. |
| GET | `/org/:orgId/employees?q=&status=&department=&has_credit=&cursor=` | ستون‌ها: نام، موبایل، بخش، جمع شارژ، مصرف، مانده، نزدیک‌ترین انقضا، آخرین استفاده (تاریخ و نام اقامتگاه) و وضعیت |
| GET | `/org/:orgId/departments` | فهرست بخش‌های موجود برای فیلتر و شارژ گروهی |
| POST | `/org/:orgId/employees` | بدنه `{ employees: [{ full_name, mobile, department? }] }`، حداکثر ۵۰۰ ردیف. ثبت دستی و گروهی. |
| POST | `/org/:orgId/employees/import/preview` | فایل xlsx، حداکثر ۲ مگابایت و ۵۰۰۰ ردیف. خواندن با `exceljs` و برگرداندن ردیف‌ها با خطای هر ردیف، بدون ذخیره. |
| POST | `/org/:orgId/employees/import/commit` | بدنه همان ردیف‌های معتبر preview با `preview_id`. ذخیره در یک تراکنش. |
| GET | `/org/:orgId/employees/import/template` | فایل نمونهٔ xlsx با سرستون‌های «نام و نام خانوادگی»، «شماره موبایل» و «بخش» در زبان مدیر |
| PATCH | `/org/:orgId/employees/:id` | بدنه `{ full_name?, department?, status? }`. فعال یا غیرفعال کردن. |
| POST | `/org/:orgId/employees/:id/mobile-code` | بدنه `{ new_mobile }`. کد تأیید با `AuthSharedService.createOtpCode` به **شمارهٔ جدید** فرستاده می‌شود (قالب `MOBILE_CHANGE_CODE`). |
| PATCH | `/org/:orgId/employees/:id/mobile` | بدنه `{ new_mobile, code }`. `validateOTP(new_mobile, code)`. شماره عوض و `user_id` پاک می‌شود و لاگ ممیزی شمارهٔ قبلی و جدید را ثبت می‌کند. |

**اعتبارسنجی هر ردیف** (مشترک بین دستی، گروهی و اکسل؛ تابع خالص با تست):
- ارقام فارسی و عربی و فاصله‌ها نرمال شوند. `+98` و `98` به `09` تبدیل شوند. الگو `^09\d{9}$`.
- خطاهای هر ردیف:
  - `INVALID_MOBILE`
  - `DUPLICATE_IN_INPUT`
  - `ALREADY_IN_ORG`
  - `ACTIVE_IN_OTHER_ORG`: پیام «این شماره در سازمان دیگری فعال است». **نام آن سازمان نمایش داده نمی‌شود.**
  - `NAME_REQUIRED`
- ردیف‌های تکراری قبل از ثبت به مدیر نمایش داده می‌شوند (بخش ۹ تصویر ۱).

## OW-5.4 — صفحه‌های Front

**پوشه:** `Front/app/(org)/org/[orgId]/` با layout اختصاصی: سایدبار مثل تصویر ۱، با نام و لوگوی سازمان بالای آن و کارت «پشتیبانی سازمانی» با شماره و ساعت کاری پایین آن. در موبایل، drawer.

**منو** (بخش ۴ تصویر ۱): داشبورد، کارکنان، شارژ اعتبار (OW-06)، فاکتورها و پرداخت‌ها (OW-06)، گزارش مصرف (OW-08)، اقامتگاه‌های سازمانی و تنظیمات (مدیران و اطلاعات سازمان).

| صفحه | محتوا |
| --- | --- |
| `page.tsx` (داشبورد) | بنر خوشامد با نام سازمان. کارت‌های تعداد کارکنان، اعتبار شارژشده، اعتبار مصرف‌شده (با درصد و نوار) و مانده (با درصد). جدول کوتاه کارکنان، کارت «موجودی سازمان» با «شارژ کارکنان» و «تاریخچهٔ تراکنش‌ها»، کارت «طرح هدیهٔ سازمانی» (درصد تخفیف قرارداد و یک مثال)، آخرین تراکنش‌ها، و کاروسل اقامتگاه‌های سازمانی. |
| `employees/page.tsx` | جستجو، فیلتر وضعیت و بخش، و جدول ستون‌های OW-5.3 با `...` عملیات. دکمه‌های افزودن کارمند، ویرایش شماره، شارژ تکی، شارژ گروهی و ورود فایل اکسل (بخش ۶ تصویر ۱). در موبایل کارت است. |
| modal «افزودن کارکنان» | سه برگه: **ثبت دستی** (ردیف‌های نام، موبایل و بخش)، **گروهی** (paste چندخطی «نام، موبایل، بخش») و **ورود از فایل اکسل** (دانلود نمونه، آپلود، جدول preview با ردیف‌های خطادار قرمز و دلیل ترجمه‌شده، و «ثبت ردیف‌های معتبر»). بعد از ثبت، گزینهٔ «همین افراد را شارژ کن» به OW-06 می‌رود. |
| modal «ویرایش شماره موبایل» (بخش ۱۰ تصویر ۱) | شمارهٔ فعلی (فقط‌خواندنی)، شمارهٔ جدید، «ارسال کد تأیید» و ورودی کد. هشدار زرد: «تغییر شمارهٔ موبایل اعتبار این کارمند را از بین نمی‌برد و فقط شماره را به‌روز می‌کند. انتقال اعتبار به شخص دیگر ممکن نیست.» |
| `properties/page.tsx` | اقامتگاه‌های سازمانی: فهرست آگهی‌های مجاز (`isOrgEligibleProperty`) با کارت فعلی آگهی Front و برچسب «ویژهٔ سازمان‌ها». فقط نمایش است و مدیر فهرست را تغییر نمی‌دهد. |
| `settings/page.tsx` | اطلاعات حقوقی سازمان (فقط‌خواندنی، با متن «برای تغییر با کارشناس جایاب تماس بگیرید») و مدیران (دعوت و حذف) |

- **API و hookها:** `Front/api_services/org/org.service.ts` و `Front/features/org/hooks/`. `orgId` همیشه از URL خوانده می‌شود.
- **متن‌ها:** namespace `org` در سه زبان. موبایل‌ها `dir="ltr"`. جدول در en چپ‌چین است.

## امنیت

- هر endpoint `OrgManagerGuard` دارد. تست: مدیر سازمان A با `orgId` سازمان B خطای 403 می‌گیرد.
- **آپلود اکسل:**
  - فقط پسوند و MIME xlsx پذیرفته می‌شود و حجم و تعداد ردیف محدود است.
  - فقط مقدار سلول‌ها خوانده می‌شود و فرمول‌ها اجرا نمی‌شوند. `exceljs` فرمول را محاسبه نمی‌کند.
  - فایل ذخیره نمی‌شود. preview فقط ۳۰ دقیقه در Redis با `preview_id` می‌ماند.
- پیام «فعال در سازمان دیگر» نام آن سازمان را لو نمی‌دهد.
- بعد از پیاده‌سازی `/security-review` اجرا شود.

## معیار پذیرش فاز

- [ ] مدیر از لینک دعوت با شمارهٔ خودش وارد می‌شود. با شمارهٔ دیگر خطای 403 می‌گیرد.
- [ ] فایل ۱۰۰۰ ردیفی با ۳ ردیف خطادار: preview سه خطای ترجمه‌شده را نمایش می‌دهد و ۹۹۷ ردیف ثبت می‌شود.
- [ ] شماره‌ای که در سازمان دیگری فعال است ثبت نمی‌شود. بعد از غیرفعال شدن در آن سازمان، ثبت می‌شود.
- [ ] تغییر شماره با کد تأیید شمارهٔ جدید انجام می‌شود و موجودی کارمند تغییر نمی‌کند.
- [ ] همهٔ صفحه‌ها در سه زبان و دو تم، و در ۳۶۰ و ۱۲۸۰ پیکسل (XC-7).
- [ ] Back و Front: lint، build و test.
