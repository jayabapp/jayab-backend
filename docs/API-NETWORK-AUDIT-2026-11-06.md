# ممیزی APIها و ارتباطات شبکهٔ جایاب

تاریخ: ۲۰۲۶/۱۱/۰۶. دامنه: Back (NestJS)، Front (Next.js) و Panel، شاخهٔ `main`، به‌علاوهٔ ضبط شبکهٔ سایت اصلی `jayab.app`. هیچ کدی در این ممیزی تغییر نکرده است.

پیوست: [فهرست کامل ۴۰۹ endpoint](./API-NETWORK-AUDIT-ENDPOINTS.md).

## روش

| منبع | کار انجام‌شده |
|---|---|
| کد Back | استخراج خودکار همهٔ کنترلرها (مسیر، متد، نسخه، گارد)، بررسی سرویس‌های خروجی، صف‌ها، کرون‌ها، پیکربندی |
| کد Front | مسیرهای API (`utils/urls.ts`)، سرویس‌ها، مسیرهای داخلی `app/api`، پروکسی، اسکریپت‌های شخص ثالث |
| سایت اصلی | ضبط درخواست‌های مرورگر در صفحهٔ اول، نتایج و آگهی (موبایل و دسکتاپ)، تست زمان پاسخ و وضعیت HTTP |

محدودیت: به سرور، nginx، لاگ‌ها و env واقعی دسترسی نبود. مواردی که به آن‌ها بستگی دارد با «نیازمند تأیید روی سرور» مشخص شده‌اند. جریان ورود و ثبت رزرو روی سایت اصلی اجرا نشد (ثبت رزرو برای میزبان واقعی پیامک و تماس می‌فرستد) و از روی کد تحلیل شد.

## خلاصهٔ مدیریتی

| اولویت | یافته | اثر |
|---|---|---|
| **بحرانی** | Back همهٔ کاربران وب را یک IP می‌بیند (سرور Next بدون انتقال IP کاربر درخواست می‌دهد) و محدودیت‌های تعداد درخواست بر اساس IP است | محدودیت سراسری ۵۰ درخواست در ۱۰ ثانیه و محدودیت ارسال کد ورود ۲۰ بار در ۱۵ دقیقه بین **همهٔ کاربران سایت** مشترک می‌شود؛ یک نفر می‌تواند با درخواست سریع، سایت یا ورود را برای همه قفل کند |
| بالا | `trust proxy` روی `true` است و IP از چپ‌ترین مقدار `X-Forwarded-For` خوانده می‌شود | اگر nginx این هدر را بازنویسی نکند، IP قابل جعل است و محدودیت‌ها و فهرست IP مجاز دور زده می‌شوند |
| بالا | کندی و خطای متناوب در سایت اصلی: یک بار ۵۰۴، یک بار ۳۰٫۷ ثانیه تا اولین بایت در `/rooms`، یک قطع اتصال | تجربهٔ کاربر و سئو؛ احتمالاً به مورد بحرانی یا کندی Back مربوط است |
| بالا | تصویر پروفایل میزبان در پاسخ عمومی آگهی، از پوشهٔ «سلفی مالک» و با رکورد کامل فایل (شناسهٔ کاربر، باکت، مسیر) | احتمال انتشار سلفی احراز هویت؛ دادهٔ داخلی بیش از نیاز |
| متوسط | صفحهٔ نتایج روی موبایل نقشه را فوراً بارگذاری می‌کند: حدود ۱٫۶ مگابایت فونت نقشه و چند کاشی، حتی اگر کاربر نقشه را باز نکند | سرعت موبایل و مصرف اینترنت کاربر |
| متوسط | هر کارت آگهی دو لینک دارد و هر کدام جدا پیش‌بارگذاری می‌شود؛ فهرست آگهی‌ها بعد از رندر سرور یک بار دیگر از مرورگر گرفته می‌شود | درخواست‌های تکراری؛ HTML صفحهٔ نتایج ۵۲۲ کیلوبایت |
| متوسط | کلید امضای «userAuth» از متغیر مدت اعتبار (`USER_AUTH_EXPIRE`) خوانده می‌شود | امروز استفاده نمی‌شود؛ اگر روزی فعال شود، توکن قابل جعل است |
| متوسط | نشانی پیش‌فرض اشتباه `https://jayaab.com` (با دو a) در `app/layout.tsx` | اگر `NEXT_PUBLIC_SITE_URL` خالی بماند، متادیتا به دامنهٔ دیگری اشاره می‌کند |
| کم | مسیرهای قدیمی بلااستفاده در Front و Back، ماژول دسته‌بندی باقی‌مانده از قالب اولیه | پیچیدگی و سطح حملهٔ اضافه |

## ۱. فهرست APIها

### Back

| بخش | تعداد | نمونه |
|---|---:|---|
| ادمین (`/api/v1/admin/...`) | ۲۳۱ | همه با `AdminJwtGuard` و کنترل دسترسی نقش‌محور |
| میزبان (`/api/v1/owner/...`) | ۴۵ | `OwnerGuard` یا `OwnerJwtGuard` |
| کاربر و عمومی | ۱۳۳ | ۴۹ مسیر بدون گارد (خواندن عمومی، کال‌بک پرداخت، فرم‌ها) |
| **مجموع** | **۴۰۹** | فهرست کامل در پیوست |

- پیشوند همه `/api` و نسخه‌بندی در مسیر (`/api/v1`، `/api/v2`) است.
- شمارش گاردها: `AdminJwtGuard` ۲۵۴، `UserJwtGuard` ۹۵، `OwnerGuard` ۳۷، `OwnerJwtGuard` ۵، `AuthThrottlerGuard` ۴، `MianJwtGuard` ۲.
- وب‌سوکت: یک gateway برای چت (`socket.io`، رویداد در حال تایپ و پیام).
- مسیرهای ادمین همه گارد دارند؛ مسیر ادمین بدون محافظ پیدا نشد.

### Front

| نوع | تعداد | توضیح |
|---|---:|---|
| ثابت‌های مسیر API در `utils/urls.ts` | ۱۱۵ | ۸ مورد هیچ‌جا استفاده نمی‌شوند (بخش ۴) |
| پروکسی مرورگر | ۱ | `/api/backend/{v1,v2}/...`، فقط مسیرهای فهرست مجاز؛ مسیرهای ادمین رد می‌شوند |
| مسیرهای داخلی Next | ۱۰ | ورود (`/api/auth/otp`، `/otp/verify`، `/session`)، نقشه (`/api/map/search`، `/reverse`)، `healthz`، `robots`، `sitemap`، `llms`، `qa-login`، `v1/revalidate-ssr` |

### Panel

همهٔ درخواست‌ها به مسیرهای `/admin/...` Back می‌روند. مسیرها پویا ساخته می‌شوند (مثل `model-props` و `update-partial`)، پس تطبیق ایستای مسیرهای بلااستفادهٔ ادمین قابل اتکا نیست.

## ۲. درخواست‌های ورودی و خروجی سرور

### ورودی

| مقصد | از کجا | محافظ |
|---|---|---|
| `jayab.app` (Next) | مرورگر کاربران، خزنده‌ها | گیت ورود فقط روی دامنهٔ تست |
| `jayab.app/api/backend/...` | مرورگر | فهرست مجاز مسیر؛ بدون محدودیت تعداد در خود Next |
| `api.jayab.app` | سرور Next، پنل، کال‌بک درگاه پرداخت، شریک «میان»، کلاینت خارجی `client/mobile-exist`، احتمالاً اپ موبایل | میان‌افزار IP و دامنه، گاردها، محدودیت تعداد |
| وب‌سوکت `api.jayab.app` | مرورگر کاربر واردشده | توکن سوکت |

### خروجی

| از | به | دلیل |
|---|---|---|
| Next | `api.jayab.app` (`NEXT_PUBLIC_BASE_URL`) | همهٔ داده‌ها؛ رندر سرور و پروکسی مرورگر |
| Next | `api.neshan.org` | جستجو و نشانی‌یابی نقشه با کلید سرویس (فقط سمت سرور) |
| Next (`proxy.ts`) | `api.jayab.app/.../redirect-check` | بررسی ریدایرکت برای **هر درخواست صفحه با ارجاع از بیرون سایت** (با کش) |
| Back | `api.sms.ir` | کد ورود و همهٔ پیامک‌های قالبی |
| Back | `portal.avanak.ir` | تماس صوتی به میزبان (رزرو با اشتراک منقضی) |
| Back | زرین‌پال (`PAYMENT_BASE_URL`)، `api.bazaar-pay.ir` | درگاه پرداخت و تأیید تراکنش |
| Back | ذخیره‌ساز ابری آروان (S3) | عکس‌ها و فایل‌ها |
| Back | Firebase Admin (سرورهای گوگل) | اعلان push |
| Back | PostgreSQL، Redis | داده، کش، صف‌ها، محدودیت‌ها |

## ۳. دامنه‌ها و سرویس‌های خارجی

ضبط‌شده در مرورگر روی سایت اصلی:

| دامنه | کاربرد | صفحه‌ها |
|---|---|---|
| `www.googletagmanager.com`، `www.google-analytics.com` | Google Tag Manager و Analytics | همه |
| `cdn.yektanet.com`، `audience.yektanet.com`، `ua.yektanet.com` | آنالیتیکس و ریتارگتینگ یکتانت | همه |
| `s1.mediaad.org`، `mediacdn.mediaad.org`، `api.mediaad.org` | ریتارگتینگ مدیااد (در هدر سایت) | همه |
| `static.neshan.org`، `api.neshan.org` | نقشه (استایل، فونت، کاشی) | نتایج، آگهی |
| `trustseal.enamad.ir` | نشان اینماد | فوتر |
| فضای ابری آروان (`*.arvanstorage.ir`) | عکس آگهی‌ها | همه |
| Firebase و `www.gstatic.com` | ثبت توکن اعلان | فقط کاربر واردشده |

نکته‌ها:
- کلید وب نشان در آدرس درخواست‌ها دیده می‌شود (طبیعی برای کلید وب). در پنل نشان باید به دامنهٔ `jayab.app` محدود باشد.
- سرویس‌های گوگل (Analytics، Tag Manager، Firebase) از داخل ایران ممکن است کند یا ناپایدار باشند. اسکریپت‌ها بعد از بارگذاری صفحه اجرا می‌شوند، ولی اعلان push به Firebase وابسته است.
- رویدادهایی که به Tag Manager فرستاده می‌شوند فقط تعداد شب، مهمان و مبلغ دارند و اطلاعات شخصی ندارند.
- یکتانت و مدیااد نشانی صفحه و رفتار کاربر را برای تبلیغات دریافت می‌کنند. این باید در سیاست حریم خصوصی سایت ذکر شود.

## ۴. APIهای بلااستفاده، قدیمی یا تکراری

| مورد | وضعیت | پیشنهاد |
|---|---|---|
| `/api/v1/banners`، `/api/v1/user/properties/search/suggestions` (نسخهٔ ۱) | فرانت فقط نسخهٔ ۲ را صدا می‌زند | اگر اپ موبایل از نسخهٔ ۱ استفاده نمی‌کند، با یک دورهٔ اعلام قبلی حذف شوند |
| ماژول `categories` (۵ مسیر عمومی) | در فرانت و پنل استفاده نمی‌شود؛ داده‌های نمونهٔ آن («ساعت مردانه»، «ماشین حساب») از قالب اولیهٔ پروژه است | حذف |
| `user/bookmarks/property-ids`، `user/favorites/property-ids`، `user/payment-gateways`، `user/submitted-forms` | در فرانت استفاده نمی‌شوند | بررسی با تیم اپ موبایل؛ در غیر این صورت حذف |
| ثابت‌های فرانت `AU1`، `AU2`، `AU3`، `AU5`، `AU6`، `AU7`، `PROFILE_UPLOAD`، `CONTENTS_QUESTIONS_RATE` | تعریف شده‌اند، استفاده نمی‌شوند | حذف |
| متدهای فرانت `AuthService.SignIn`، `confirmOtpRegister`، `ChatService.GetNotifs`، `GetNotifsBadge`، `GetTickets`، `PostTicket`، `CityService.GetProvince`، `PropertyService.UpdatePropertyStatus`، `UpdatePropertyPrice` | هیچ‌جا صدا زده نمی‌شوند؛ بعضی به مسیرهایی اشاره دارند که در Back وجود ندارد (مثل `/user/forget-password/...`) | حذف |
| `client/mobile-exist` و مسیرهای `mian` | برای شرکای خارجی؛ مستندی در مخزن ندارند | مستند شود چه کسی و با چه قراردادی از آن‌ها استفاده می‌کند |
| کرون‌های `seo-page-analyze` (هر ۱۰ ثانیه) و `sync-seo-page-analyze-and-sitemap` | با `return` غیرفعال شده‌اند ولی هنوز زمان‌بندی می‌شوند | حذف یا فعال‌سازی آگاهانه |
| کلید و سازندهٔ توکن `userAuth` و گارد `UserAuthJwtGuard` | هیچ مسیری از آن استفاده نمی‌کند | حذف، یا اصلاح کلید (بخش ۷) |

مستندات: Back توضیح Swagger برای بیشتر مسیرها دارد، ولی Swagger روی سرور عمومی در دسترس نیست و مستند مرکزی برای مسیرهای شرکای خارجی وجود ندارد.

## ۵. درخواست‌های غیرضروری، تکراری یا کند

| مورد | شاهد | پیشنهاد |
|---|---|---|
| بارگذاری فوری نقشه روی موبایل | ۱۶ فایل فونت نقشه (هر کدام ۶۵ تا ۱۲۵ کیلوبایت، حدود ۱٫۶ مگابایت) و ۶ کاشی پیش از تعامل | بارگذاری نقشه فقط وقتی کاربر آن را باز می‌کند؛ محدود کردن فونت‌ها به یک وزن |
| دو لینک برای هر کارت | ۶۰ لینک برای ۳۰ کارت؛ برای هر کارت دو پیش‌بارگذاری RSC | یک لینک برای هر کارت، یا خاموش کردن پیش‌بارگذاری لینک دوم |
| دریافت دوبارهٔ فهرست | HTML صفحهٔ نتایج کارت‌ها را دارد، ولی مرورگر همان صفحهٔ اول را دوباره می‌گیرد | **نیازمند بررسی**: احتمالاً کلید کش سرور و مرورگر یکی نیست |
| حجم HTML صفحهٔ نتایج | ۵۲۲ کیلوبایت | بعد از رفع موارد بالا دوباره اندازه‌گیری شود |
| کندی متناوب | ۳۰٫۷ ثانیه تا اولین بایت `/rooms` یک بار، ۵۰۴ یک بار؛ معمولاً حدود ۱ ثانیه | بررسی لاگ Back و Next در همان بازه؛ تنظیم مهلت درخواست سمت سرور Next |
| بررسی ریدایرکت در هر بازدید ورودی | `proxy.ts` برای هر صفحه‌ای که ارجاع‌دهنده‌اش خود سایت نیست (مثل ورود از گوگل) از Back استعلام می‌گیرد | با کش جواب می‌دهد؛ ولی بهتر است فهرست ریدایرکت‌ها یک‌جا در حافظه کش شود |
| Sitemap | در هر درخواست از کل دیتابیس ساخته می‌شود (فقط با محدودیت تعداد) | کش در Back یا ساخت زمان‌بندی‌شده |
| بازگشت به برگه | `refetchOnWindowFocus` به‌صورت سراسری روشن است | برای داده‌های کم‌تغییر (شهرها، گزینه‌ها) خاموش شود |
| پولینگ | رزرو مهمان هر ۳۰ ثانیه فقط وقتی در انتظار است؛ رزروهای میزبان هر ۳۰ دقیقه | مناسب |

## ۶. وب‌هوک‌ها، سرویس‌های ثالث، کرون‌ها و کارهای پس‌زمینه

### وب‌هوک‌ها و کال‌بک‌ها

| مسیر | فرستنده | محافظت |
|---|---|---|
| `GET /api/v1/payments/callback` | درگاه پرداخت | تراکنش از سمت سرور با درگاه تأیید می‌شود (درست است) |
| `POST /api/v1/mian/properties/webhooks/actions` | شریک «میان» (بستن و باز کردن روزهای تقویم) | توکن JWT با کلید مشترک؛ هر توکن معتبر به همهٔ اقامتگاه‌ها دسترسی دارد |
| `POST /api/v1/mian/properties` | شریک «میان» | همان |

### کرون‌ها (فقط در محیط production فعال)

| نام | تناوب | کار |
|---|---|---|
| `delete-excel-files` | هر ۳۰ دقیقه | پاک کردن خروجی‌های اکسل |
| `property-subscription-reminder` | هر دقیقه، ساعت ۱۰ تا ۱۴ | پیامک و اعلان یادآوری تمدید **یک** آگهی در هر اجرا |
| `advisor-subscription-reminder` | هر دقیقه، ساعت ۱۰ تا ۱۴ | همان برای مشاور |
| `property-promote-remover` | هر دقیقه | حذف نردبان منقضی، **یک** آگهی در هر اجرا |
| `enable-chat-in-expired-property` | هر ۶ ساعت | فعال کردن چت آگهی‌های منقضی |
| `seo-page-analyze`، `sync-seo-page-analyze-and-sitemap` | هر ۱۰ ثانیه و هر ۶ ساعت | غیرفعال (بخش ۴) |

نکته‌ها:
- یادآورها و حذف نردبان در هر اجرا فقط یک مورد را پردازش می‌کنند: حداکثر ۳۰۰ یادآور در روز. اگر بیشتر باشد، بعضی جا می‌مانند.
- اگر Back روی سرور در چند نمونه (مثلاً حالت cluster در PM2) اجرا شود، همهٔ کرون‌ها در هر نمونه اجرا می‌شوند و پیامک یادآور ممکن است تکراری شود. **نیازمند تأیید روی سرور.** راه‌حل: قفل Redis برای هر کرون، یا اجرای کرون فقط در یک نمونه.

### صف‌ها (Bull روی Redis)

| صف | کار |
|---|---|
| `RESERVE_QUEUE` | پیامک رزرو به میزبان، تماس صوتی آوانک، انقضای خودکار رزرو، پیامک پیشنهاد اقامتگاه به مهمان |
| `CHAT_MESSAGE_SMS_QUEUE` | پیامک یادآوری پیام چت به میزبان |
| `PAYMENT_SMS_QUEUE` | پیامک پرداخت |
| `CALL_LOG_QUEUE` | ثبت کلیک تماس |
| `VIEW_COUNT_QUEUE` | شمارش بازدید |

## ۷. احراز هویت، سطح دسترسی و امنیت

| موضوع | وضعیت | پیشنهاد |
|---|---|---|
| ورود کاربر | کد یک‌بارمصرف پیامکی؛ شمارندهٔ تلاش برای هر کد (`MAX_OTP_ATTEMPTS`)؛ محدودیت تعداد با Redis | درست؛ ولی محدودیت به IP وابسته است (ردیف بعد) |
| IP کاربر در Back | سرور Next IP کاربر را منتقل نمی‌کند؛ `trust proxy: true` | Next هدر IP واقعی را با یک کلید مشترک بفرستد؛ Back فقط از Next به آن اعتماد کند و `trust proxy` روی تعداد دقیق پروکسی‌ها تنظیم شود |
| CORS | `enableCors({})` همهٔ مبدأها را می‌پذیرد؛ میان‌افزار جدا با **شامل بودن** نام دامنه چک می‌کند (`https://jayab.app.evil.com` هم رد می‌شود) | فهرست دقیق مبدأها با برابری کامل؛ این میان‌افزار امنیت واقعی نیست، چون هدر Origin در درخواست‌های غیرمرورگری قابل جعل است |
| توکن کاربر | در کوکی httpOnly نگه داشته و از پروکسی Next ضمیمه می‌شود | درست |
| کلید `userAuth` | `secret: process.env.USER_AUTH_EXPIRE` | به `USER_AUTH_SECRET` اصلاح یا کامل حذف شود |
| شریک «میان» | هر توکن معتبر به همهٔ اقامتگاه‌ها دسترسی دارد | محدود کردن به اقامتگاه‌های همان شریک و ثبت لاگ |
| کلاینت `mobile-exist` | کلید API و IP؛ مقایسهٔ کلید زمان‌ثابت نیست و IP قابل جعل است | مقایسهٔ زمان‌ثابت؛ بعد از اصلاح IP، محدودیت IP معنا پیدا می‌کند |
| نشانی بازگشت پرداخت | `redirect_url` از کاربر گرفته و بدون اعتبارسنجی در صفحهٔ نتیجهٔ پرداخت گذاشته می‌شود | فقط مسیرهای داخلی سایت پذیرفته شوند |
| بازسازی کش Front | توکن از query هم پذیرفته می‌شود؛ محدودیت تعداد با `X-Forwarded-For` قابل جعل است | فقط هدر؛ همان اصلاح IP |
| فرم‌ها و سؤال عمومی | `POST submitted-forms` و `POST content-questions` بدون گارد | کپچا یا محدودیت مخصوص |
| شمارش بازدید | `PUT .../view` و `PATCH banners/:id` عمومی | قابل دستکاری آمار؛ اولویت کم |
| لاگ | `console.log({ ip })` در هر درخواست ورود | حذف یا انتقال به لاگر با سطح مناسب |

## موارد نیازمند تأیید روی سرور

1. تنظیم nginx برای `X-Forwarded-For` (بازنویسی یا افزودن) در هر دو vhost.
2. نشانی‌ای که سرور Next با آن به Back وصل می‌شود (عمومی یا داخلی) و IP که Back در لاگ برای درخواست‌های وب می‌بیند.
3. تعداد نمونه‌های اجرای Back (برای کرون‌های تکراری).
4. مقدار `NEXT_PUBLIC_SITE_URL` روی سرور (برای نشانی پیش‌فرض اشتباه).
5. محدودیت دامنه برای کلید وب نشان در پنل نشان.
6. فهرست کلاینت‌های خارجی API (اپ موبایل، «میان»، کلاینت `mobile-exist`).
