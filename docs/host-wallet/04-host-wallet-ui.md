# ۰۴ — کیف پول میزبان (Back + Front)

**وابستگی:** HW-02 و HW-03.
**خروجی:** نمایش شفاف طلب و سوابق مالی میزبان، شامل **سه وضعیت** (در انتظار تسویه، قابل تسویه، تسویه‌شده)، بنر وضعیت حساب بانکی و لیست درآمد رزروها با مرحله‌ها و شکایت‌ها. **بدون امکان برداشت.**

**تصمیم کارفرما:** کیف پول میزبان سه وضعیت دارد:

| وضعیت | معنی |
| --- | --- |
| در انتظار تسویه | سهم میزبان مشخص شده ولی هنوز آزاد نشده است |
| قابل تسویه | مهلت بررسی تمام شده و مبلغ آمادهٔ واریز است |
| تسویه‌شده | مبلغ به حساب بانکی میزبان واریز شده است |

تفاوت «قابل تسویه» و «واریزشده» مهم است، چون انتقال بانکی ممکن است به چرخه‌های پایا و تعطیلات برخورد کند. وضعیت‌های داخلی دفترکل بیشترند و در نمایش به این سه نگاشت می‌شوند:

| bucket داخلی | نمایش به میزبان |
| --- | --- |
| `PENDING` | در انتظار تسویه، با «آزادسازی: {تاریخ و ساعت}» |
| `ON_HOLD` | در انتظار تسویه، با «متوقف تا بررسی گزارش مهمان» یا «متوقف تا بررسی مالی» |
| `AVAILABLE` | قابل تسویه |
| `PROCESSING` | قابل تسویه، با «در حال واریز · ثبت {تاریخ}. واریز بانکی ممکن است به چرخهٔ پایا یا تعطیلی برخورد کند.» |
| `SETTLED` | تسویه‌شده، با شمارهٔ پیگیری |
| `VOID` | نمایش داده نمی‌شود. فقط مبلغ اصلاح‌شده در ردیف رزرو دیده می‌شود. |

این جایگزین چهار کارت سند اولیهٔ کیف پول است. پنل مالی همچنان وضعیت‌های داخلی را جدا می‌بیند.

## HW-4.1 — APIها (Back)

**پوشه:** `Back/src/wallet/roles/owner/wallet.controller.ts`، با گروه مسیر `owner/wallet` و گاردهای مالک.

| متد | مسیر | خروجی |
| --- | --- | --- |
| GET | `/api/v1/owner/wallet/summary` | `{ awaiting: { total, on_hold }, settleable: { total, in_transfer }, settled, bank_status, settlement_blocked: 'BANK_NOT_VERIFIED' │ null, next_release_at }`. `awaiting = PENDING + ON_HOLD` و `settleable = AVAILABLE + PROCESSING`. |
| GET | `/api/v1/owner/wallet/earnings?cursor=` | لیست صفحه‌بندی‌شده به ازای هر رزرو (پایین) |
| GET | `/api/v1/owner/wallet/settlements/:id/receipt` | لینک موقت ۵ دقیقه‌ای رسید، فقط برای حوالهٔ تأییدشدهٔ خود میزبان |

- **مانده‌ها** از `WalletService.accountBalances` حساب `HOST_RECEIVABLE` همین کاربر (HW-2.3) گرفته می‌شوند. `VOID` نمایش داده نمی‌شود. کیف پول شخصی همین کاربر (شارژ و کارت هدیه، OW-01) حساب جداست و در این صفحه جمع زده نمی‌شود. فقط یک لینک «کیف پول شخصی من» به `/profile/wallet` نمایش داده می‌شود.
- **هر ردیف `earnings`:**

```ts
{
  reserve_id, reserve_code, property: { id, title },
  check_in, check_out, nights,
  guest_paid, fee_amount, host_amount,          // from the snapshot: fixed at payment time
  canceled: { refund_amount, host_amount } | null, // from ReserveCancellation, when there is one
  complaint: { status, opened_at, refund_amount? } | null, // HW-09
  display_status: 'AWAITING'│'SETTLEABLE'│'SETTLED'│'PARTIAL',
  stages: [{ seq, amount, release_at, display_status, in_transfer: boolean, on_hold: boolean }],
  release_at,                                    // next unreleased stage
  settlement: { tracking_code, paid_on, has_receipt } | null   // only after SETTLED
}
```

- `display_status` و `stages` از `reserveHostBalances` و جدول نگاشت بالا محاسبه می‌شوند. اگر مرحله‌ها در وضعیت‌های مختلف باشند، `PARTIAL` است.
- شمارهٔ پیگیری و رسید **فقط بعد از تأیید تسویه** برگردانده می‌شوند (سند، بند ۷). حوالهٔ `PROCESSING` فقط «در حال تسویه» نمایش داده می‌شود.
- کوئری با cursor روی `reserve_financial_snapshots` (ایندکس `host_user_id`) و صفحه‌های ۲۰تایی است. مانده‌ها با یک `groupBy` برای همان صفحه گرفته می‌شوند.

## HW-4.2 — صفحهٔ کیف پول (Front)

- **مسیر:** `Front/app/(profile)/profile/(owner)/owner/wallet/page.tsx`.
- **منو:** «کیف پول جایاب» در `Front/features/user/hooks/useProfileMenu.ts`، کنار «اطلاعات تسویه‌حساب».
- **ساختار** (مرجع چیدمان: بخش «کیف پول میزبان» در [Artifact](https://claude.ai/artifact/A4SqQ8eT37zewT9yyspNMs)، با ظاهر design system Front):
  1. **بنر وضعیت حساب بانکی:**
     - اگر `settlement_blocked = BANK_NOT_VERIFIED`: «تسویه متوقف تا تأیید حساب بانکی. درآمد رزروهای شما ثبت می‌شود اما تا تکمیل و تأیید اطلاعات بانکی واریزی انجام نمی‌شود.» با دکمهٔ «تکمیل اطلاعات تسویه».
     - اگر در انتظار بررسی است، بنر خنثی «اطلاعات بانکی شما در حال بررسی است».
  2. **سه کارت خلاصه:**
     - **در انتظار تسویه:** مبلغ و «آزادسازی بعدی: {تاریخ و ساعت}». اگر `on_hold > 0`، سطر «متوقف تا بررسی: {مبلغ}».
     - **قابل تسویه:** مبلغ. اگر `in_transfer > 0`، سطر «در حال واریز: {مبلغ}».
     - **تسویه‌شده:** مبلغ.
     - زیر کارت‌ها یک خط توضیح ثابت: «سهم شما ۲۴ ساعت بعد از تحویل اقامتگاه به مهمان قابل تسویه می‌شود، اگر گزارش مشکلی ثبت نشده باشد. در اقامت یک‌شبه، بعد از خروج مهمان. در اقامت‌های طولانی، به‌صورت مرحله‌ای.»
  3. **لیست درآمد رزروها** با ستون‌های سند، بند ۷:

| ستون | محتوا |
| --- | --- |
| کد رزرو و اقامتگاه | با لینک به جزئیات همان رزرو در رزروهای مالک |
| تاریخ اقامت | ورود، خروج و تعداد شب |
| مبلغ کل و سهم جایاب | مبالغ قطعی‌شده در زمان پرداخت |
| سهم میزبان | مبلغ طلب. اگر لغو شده، مبلغ قبلی خط‌خورده و مبلغ جدید با برچسب «لغو طبق قانون کنسلی». |
| وضعیت تسویه | chip یکی از سه وضعیت. برای اقامت مرحله‌ای «مرحلهٔ ۱ از ۳ قابل تسویه» با جزئیات مرحله‌ها در باز شدن ردیف. برای رزرو با گزارش باز مهمان، chip نارنجی «متوقف تا بررسی». |
| شمارهٔ پیگیری و رسید | فقط بعد از تسویه |

     در دسکتاپ جدول است و در موبایل کارت. صفحه‌بندی بی‌نهایت با الگوی `OwnerReservationList` است.
- **قواعد سند (بند ۹):**
  - هیچ دکمهٔ «برداشت وجه» ساخته نشود.
  - هیچ‌جا عبارت «شارژ» استفاده نشود. عنوان لیست «ثبت طلب در کیف پول جایاب» است.
  - **میزبانی که هیچ طلبی ندارد:** حالت خالی «درآمد رزروهایی که از طریق جایاب پرداخت می‌شوند اینجا ثبت می‌شود. برای آگهی‌های دارای اشتراک و رزرو مستقیم، درآمد رزرو در این کیف پول ثبت نمی‌شود.»
- **API:** `Front/api_services/wallet/wallet.service.ts` با `apiCall`، hookهای `useWalletSummary` و `useWalletEarnings` در `Front/features/wallet/hooks/` با react-query مثل `features/reservations/api`.
- **متن‌ها:** namespace `wallet` در `Front/messages/{fa,ar,en}.json`. اعداد با فرمت‌کنندهٔ موجود پروژه.

## HW-4.3 — اتصال از رزروهای مالک

کارت رزرو ۹۰ در رزروهای مالک (RS-4.2) سطر «سهم شما در کیف پول جایاب ثبت شد · {وضعیت}» و لینک به `/profile/owner/wallet` داشته باشد. وضعیت از `owner.service` بستهٔ پشتیبانی با فیلد `wallet_status` برمی‌گردد که از `reserveHostBalances` محاسبه می‌شود.

## معیار پذیرش فاز

- [ ] بعد از یک رزرو سه‌شبه، کارت «در انتظار تسویه» مبلغ ۸۰٪ را با زمان آزادسازی (۲۴ ساعت بعد از تحویل) نمایش می‌دهد. بعد از آن به «قابل تسویه» می‌رود و بعد از ثبت حواله «در حال واریز» زیر همان کارت دیده می‌شود.
- [ ] رزرو ۲۰ شبه سه مرحله دارد و هر مرحله سر وقت قابل تسویه می‌شود. رزرو با گزارش باز «متوقف تا بررسی» نمایش داده می‌شود.
- [ ] صفحه فقط سه کارت دارد.
- [ ] بنر توقف تسویه تا تأیید شبا نمایش داده می‌شود.
- [ ] شمارهٔ پیگیری فقط بعد از تأیید تسویه دیده می‌شود و رسید فقط برای خود میزبان باز می‌شود.
- [ ] هیچ دکمهٔ برداشت و هیچ عبارت «شارژ» در صفحه نیست.
- [ ] میزبان دیگر به `GET /owner/wallet/settlements/:id/receipt` حوالهٔ کس دیگری خطای 403 می‌گیرد.
- [ ] fa، ar و en، روشن و تاریک، ۳۶۰ و ۱۲۸۰ پیکسل. Front: lint و build.
